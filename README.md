# 결계 (GYEOLGYE / WARD)

판정(Assessment)과 검증(Runtime Detection)을 잇는 도구. 금융회사가 내부업무망에 SaaS를 도입할 때 필요한 "이용자의 고유식별정보 또는 개인신용정보를 처리하지 않을 것" 요건(전자금융감독규정 시행세칙 제2조의3 제1항 제3호, 2026.4.20 신설)의 검토를 구조화한다. 데모 단계.

## 배경

2026년 4월 20일 시행세칙 개정으로 금융회사는 혁신금융서비스 지정 없이 내부업무망에서 SaaS를 쓸 수 있게 됐다. 진입 관문인 위 요건에서 '처리'의 정의는 감독규정과 시행세칙 어디에도 없고, 금융보안원 CSP 안전성 평가는 처리 관련 항목을 평가범위에서 제외하며(FAQ 첨부2), 판정 기준 수립은 각 금융회사에 위임되어 있다(해설서 6장). 이 도구는 그 판정을 답할 수 있는 질문들로 분해하고, 판정이 남긴 빈틈을 운영 중 탐지로 메운다.

## 구성

```
index.html    판정 워크벤치(W) + 운영 중 검증 데모. 서버 없이 열린다
engine.js     결합 탐지 엔진(D). 브라우저와 Node 양쪽에서 동작
eval/         측정 하네스(L). 합성 문서 생성 + 정밀도·재현율 채점
SPEC.md       명세: 네 요소(W/D/E/L), 파이프라인, 불변 원칙
```

데모와 측정 하네스가 **같은 엔진**을 쓴다. 시연한 것과 측정한 것이 갈라지지 않게 하기 위해서다.

## 실행

판정 워크벤치는 `index.html`을 브라우저에서 열면 된다. 빌드도 서버도 필요 없다.

측정은 Node로 돌린다.

```bash
node eval/run.js --docs 30
```

## 탐지 엔진의 3층

| 층 | 대상 | 방법 | 성격 |
|---|---|---|---|
| 규칙 | 주민번호, 카드번호, 연락처 | 정규식 + 체크섬·Luhn 검증 | 결정적. 브라우저에서도 동작 |
| 식별정보 | 이름 등 | 호칭 패턴 + 지시어 제외 | "해당 고객" 같은 지시어를 이름으로 잡지 않는다 |
| 결합 | 식별정보 × 신용정보 문맥 | 로컬 소형 LLM (없으면 규칙 근사) | 문맥 이해가 필요한 지점 |

위반 확정은 LLM이 아니라 코드가 한다. LLM 출력은 근거 스팬이 원문에 실제로 존재하는지 검증한 뒤에만 후보로 채택된다(환각 차단). 감사 증적은 같은 입력에 같은 결과가 나와야 하기 때문이다.

케이스 유형별 재현율에서 이 프로젝트의 핵심 근거가 나온다.

| 유형 | 규칙층만 | 규칙+휴리스틱 |
|---|---|---|
| 주민번호 | 100% | 100% |
| 카드번호 | 100% | 100% |

줄을 넘어가는 결합과 지시어로 이어지는 결합은 규칙으로 구조적으로 잡히지 않는다. 이 두 유형이 전체 위반의 약 40%다. 문맥 이해가 필요한 지점이 정확히 여기이고, 로컬 LLM이 투입되는 이유다.

## 로컬 LLM 연결

```bash
brew install ollama
OLLAMA_ORIGINS="*" ollama serve          # 브라우저 데모에서 호출하려면 origin 허용 필요
ollama pull hf.co/mykor/Midm-2.0-Base-Instruct-gguf:Q4_K_M
```

모델이 뜬 상태에서 `index.html`을 새로고침하면 검증 데모에 LLM 모드가 열린다. 측정은 이렇게 돌린다.

```bash
node eval/run.js --llm --docs 30
```

기본 모델은 KT의 **Mi:dm 2.0 Base (11.5B)**다. MIT 라이선스라 국내 모델 중 상업 이용 제약이 가장 적고, 한국어 중심으로 학습돼 결합 판단 같은 한국어 문맥 과제에 유리하다. Q4_K_M 기준 7.03GB로 통합 메모리 16GB 이상이면 실용적으로 돌아간다.

금융사 단말에 직접 배포하는 시나리오에서는 같은 계열의 **Mi:dm 2.0 Mini (2.3B, 1.43GB)**를 쓴다. 두 크기의 성능 차이는 측정 하네스로 잰다.

| 모델 | 라이선스 | 상업 이용 | 역할 |
|---|---|---|---|
| Mi:dm 2.0 Base (KT, 11.5B) | MIT | 가능 | 기본값 |
| Mi:dm 2.0 Mini (KT, 2.3B) | MIT | 가능 | 온디바이스 배포 시나리오 |
| Qwen3-4B-Instruct-2507 | Apache 2.0 | 가능 | 범용 다국어 기준선 |
| EXAONE 3.5 2.4B (LG) | EXAONE License (NC) | 불가 | 한국어 비교군, 연구·측정 한정 |
| Gemma 3 4B | Gemma Terms of Use | 조건부 | 비교군 |

대회 출품과 논문은 상업적 이용이 아니라서 EXAONE의 비상업 조항이 막지 않는다. 막는 것은 제품화 국면이다. Mi:dm은 MIT라 그 구분 자체가 필요 없다.

```bash
node eval/run.js --llm --model qwen3:4b-instruct-2507-q4_K_M --docs 30
```

## 측정 방법: 생성이 곧 라벨

실제 금융 문서는 그 자체가 개인신용정보라 측정에 쓸 수 없다. 대신 위반을 직접 심어 문서를 만든다. 무엇을 어디에 심었는지 알기 때문에 정답지가 라벨링 비용 없이 생긴다. 놓친 유형은 다음 세대 생성 목표로 되먹여 어려운 케이스를 증식시킨다.

같은 seed면 같은 데이터가 나온다. 실험 재현을 위해서다.

## 고지

본 도구는 법적 판단을 대행하지 않는다. 판단에 필요한 근거와 구조를 제공할 뿐이며, 최종 판단과 책임은 검토자와 소속 기관에 있다. SaaS별 근거 데이터는 2026년 8월 각 벤더 공개 관리자 문서 조사 기준이며 요금제와 기능은 변경될 수 있다.
