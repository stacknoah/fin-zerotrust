# 결계 (GYEOLGYE / WARD)

판정(Assessment)과 검증(Runtime Detection)을 잇는 도구. 금융회사가 내부업무망에 SaaS를 도입할 때 필요한 "이용자의 고유식별정보 또는 개인신용정보를 처리하지 않을 것" 요건(전자금융감독규정 시행세칙 제2조의3 제1항 제3호, 2026.4.20 신설)의 검토를 구조화하는 도구다. 데모 단계.

## 배경

2026년 4월 20일 시행세칙 개정으로 금융회사는 혁신금융서비스 지정 없이 내부업무망에서 SaaS를 쓸 수 있게 됐다. 진입 관문인 위 요건에서 '처리'의 정의는 감독규정과 시행세칙 어디에도 없고, 금융보안원 CSP 안전성 평가는 처리 관련 항목을 평가범위에서 제외하며(FAQ 첨부2), 판정 기준 수립은 각 금융회사에 위임되어 있다(해설서 6장). 이 도구는 그 판정을 답할 수 있는 질문들로 분해한다.

## 사용

```
index.html을 브라우저에서 연다. 서버, 빌드, 외부 통신 없음.
```

6단계로 진행된다: 대상 선택, 유입 데이터 성격, L1 시스템 필드, L2 사용자 자유 입력, L3 시스템 부수 생성, 판정. 판정 결과에서 검토서(인쇄용)를 생성해 도입 품의와 반기 자체평가에 첨부하는 흐름을 시연한다.

## 판정 구조

- 처리가 일어나는 경로를 3층으로 분해한다. L1 시스템 필드(제품이 필드 단위로 다루는 데이터), L2 사용자 자유 입력(문서·채팅·회의 본문), L3 시스템 부수 생성(검색 색인, 자동 녹취, AI 학습, 보존 사본)
- 합부 판정은 전부 결정 트리(결정적 로직)가 수행한다. 같은 입력이면 언제나 같은 결과가 나온다
- SaaS별 근거(차단 수단의 존재, 제공 요금제, 공식 문서 원문 인용)는 사전 수집 데이터로 내장되어 있다. 본품에서는 LLM이 공개 관리자 문서에서 근거를 실시간 추출하는 구조로 확장한다

## 데이터

`EVIDENCE` 상수에 SaaS 5종(Microsoft 365, Slack, Notion, Zoom, NHN 두레이)의 근거 30건이 들어 있다. 2026년 8월 각 벤더 공개 관리자 문서 조사 기준이며 항목마다 출처 URL과 원문 인용이 붙어 있다. 요금제와 기능은 변경될 수 있으므로 원문 링크에서 최신 상태를 확인해야 한다. 확신도가 낮은 항목은 화면에 "원문 확인 필요"로 표시된다.

## 고지

본 도구는 법적 판단을 대행하지 않는다. 판단에 필요한 근거와 구조를 제공할 뿐이며, 최종 판단과 책임은 검토자와 소속 기관에 있다.
